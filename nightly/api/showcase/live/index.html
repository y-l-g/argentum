The live feed: a Topcoat shard whose WebSocket connection keeps every open page current.

The page renders live_feed, a shard, so a write re-renders the list without touching the page around it. The shard’s body is a live! region that calls connected: during the HTTP render it emits the newest users and finishes, and the browser then opens a WebSocket and renders the shard again. On that render the body emits the current rows and waits on the board’s wake channel, re-reading and emitting again after every write. The connection belongs to the shard, so the rest of the shell stays on HTTP and no polling script runs.

The rows come from the request’s own database, so one router’s feed never shows another router’s writes. The wake channel is a process-global because Panel::app_context carries only the Db; an app that owns a context of its own keeps the sender beside it instead.
